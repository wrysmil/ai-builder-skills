# UI 设计层规则（视觉方向）

本文件解决「原型能点但看起来很模板」的问题。生成原型前必须先定视觉方向，再写代码。

## 1. 视觉方向必须先定，不能边写边想

在动手写 HTML 之前，先产出一份**设计方向卡**（写在原型同目录的 `<项目名>-UI设计说明.md`，或在需求说明面板顶部给出摘要）：

| 项 | 内容 |
| --- | --- |
| 产品类型 | 后台管理 / 电商 / SaaS / 数据看板 / 落地页 / 移动端 / 工具类 |
| 使用者与场景 | 谁在什么场景下用（一线操作员？管理者每日巡检？移动中单手操作？） |
| 气质关键词 | 3 个词，如「克制、专业、高密度」 |
| 视觉参考 | 1-2 个参照物（具体产品或风格名），不是「类似某某」而是可描述的具体特征 |
| 布局骨架 | 侧边栏 / 顶栏 / 双栏 / 单栏 / 卡片流 |
| 信息密度 | 高（表格为主）/ 中 / 低（引导为主） |
| 强调色与语义色 | 主色、CTA 色、成功/警告/危险各一个，及其 hex |
| 字体与字号层级 | 中文正文、表格数字、标题三级 |
| 明确排除 | 至少 2 条「本次不做」的视觉套路 |

没有设计方向卡，不允许开始生成 HTML。

## 2. 配色：先检索，再决定

可用时用 `ui-ux-pro-max` 辅助检索。用户提供设计系统时优先引用其中的规则。

```bash
python <ui-ux-pro-max技能目录>/scripts/search.py "<产品类型> <行业> <关键词>" --design-system -p "<项目名>"
```

可选补充检索：

```bash
# 风格关键词
python <ui-ux-pro-max技能目录>/scripts/search.py "<style 关键词>" --domain style
# 字体搭配
python <ui-ux-pro-max技能目录>/scripts/search.py "<字体关键词>" --domain typography
# 无障碍与交互规范
python <ui-ux-pro-max技能目录>/scripts/search.py "accessibility contrast focus" --domain ux
```

将采用的风格、配色、排版和布局写入方向卡，注明来源与取舍。

若检索结果与用户已指定的品牌色或设计规范冲突，**以用户为准**，并在设计方向卡里记录冲突与取舍。

## 3. 用 CSS 变量承载设计令牌

原型一律用 CSS 变量表达设计令牌，禁止在规则里散落硬编码色值：

```css
:root {
  --brand: #2563eb;      /* 主色 */
  --brand-soft: #eff6ff; /* 主色浅底 */
  --accent: #f97316;     /* CTA 强调色 */
  --ink: #172033;        /* 主文字 */
  --muted: #6b7280;      /* 次要文字 */
  --line: #e5e7eb;       /* 分隔线 */
  --surface: #ffffff;    /* 卡片面 */
  --page: #f5f7fb;       /* 页面底 */
  --success: #15803d;    /* 成功/启用 */
  --warning: #b45309;    /* 警告/待处理 */
  --danger: #b91c1c;     /* 危险/停用/失败 */
  --radius: 12px;
  --space-1: 4px; --space-2: 8px; --space-3: 12px;
  --space-4: 16px; --space-5: 24px; --space-6: 32px;
  --shadow: 0 10px 30px rgba(15, 23, 42, 0.08);
  --font-sans: "Source Han Sans SC", "Microsoft YaHei", system-ui, sans-serif;
  --font-mono: "JetBrains Mono", Consolas, monospace;
}
```

要求：

- 间距只用 `--space-*` 这一套刻度（4/8/12/16/24/32），不出现 `13px`、`17px` 这类随手值。
- 圆角只用 `--radius` 及它的 1/2 倍。
- 语义色表达状态：**状态永远同时用颜色 + 文字**，不能只靠色块区分（无障碍要求，也是原型评审的可读性要求）。
- 深色模式如需要，用 `@media (prefers-color-scheme: dark)` 覆盖同一组变量，不另起一套变量名。

## 4. 排版与数字

- 中文正文 13-14px，表格 13px，页面标题 18-20px，卡片小标题 14-15px。
- 正文行高 1.6；表格行高 1.5，行高不低于 36px。
- 表格中的**数字列右对齐**，文本列左对齐，状态列居中。
- 金额、编号、代码、日期用等宽字体或 `font-variant-numeric: tabular-nums`，避免列表页数字左右跳动。
- 禁止全大写英文 eyebrow 当作中文界面的标题装饰；中文界面的层级靠字号、字重、留白建立。

## 5. 布局与密度

- 后台管理默认：顶栏（高 56px）+ 侧边栏（宽 200-240px）+ 内容区。
- 内容区最大宽度按业务定：表格型不限宽，表单型收在 720-960px。
- 表格页默认带工具栏（查询条件 + 操作按钮），查询区与结果区之间用 16px 间距分隔，不要用多层卡片堆叠。
- 卡片只用于分组，**不要卡片套卡片**；信息区用留白和分隔线建立层次。
- 弹窗宽度：确认类 360-420px，表单类 480-640px，详情抽屉不超过视口 40%。

## 6. 反套路清单（出现即判不合格）

以下都是 AI 生成界面的典型特征，出现就要改：

- 紫蓝渐变铺满整个 hero 或卡片。
- 全部使用 Inter / Roboto / 系统默认 sans，中文界面用 `PingFang SC` 之外再无第二字体层级。
- 每个区块都居中 + 大标题 + 副标题 + 三个图标的「SaaS 落地页」套路用在后台系统里。
- 一律 16px 圆角 + 24px 阴影 + 灰底卡片网格。
- 表格只显示一列假数据，行高 28px，没有真实业务密度。
- 图标全是 emoji 或同色线性小方块。
- 空状态只有「暂无数据」四个字，没有解释和下一步操作。
- 状态用红黄绿三个圆点表示，没有文字。

## 7. 交付前视觉自检

- 灰度查看：把页面截图转灰度，层次还在吗？
- 缩放检查：1440×900 / 1680×1050 / 1920×1080 下有没有错位或横向溢出？
- 空态检查：清空列表、搜索无结果、保存失败三种情况各自有文案和下一步吗？
- 对比度检查：正文与背景、正文与次要文字是否都达到 4.5:1？
- 令牌检查：有没有漏网的硬编码色值和随手间距？
