# 开工前需求分析与底座评估

从用户要完成的任务出发，依次判断品类、拆解能力、对照底座、沉淀方案。业务证据用来确认需求，技术证据用来判断候选能覆盖什么。

## 分阶段协作

- 新项目从第 1 步开始。每轮只推进当前阶段，先完成该阶段内可执行的工作，再交付阶段结果和需要用户确认的具体决定。后续阶段等当前结果经用户明确确认后启动，第 4 步也需用户确认才算定稿。
- 用户明确接受当前结果或要求基于当前结果进入指定下一步时，记录该决定并继续。静默、跳过问题、单纯补充资料或要求继续研究当前阶段，均保留待确认状态。收到修订意见时先更新本阶段结果。前提变化时回到最早受影响的阶段，下游结论标为待复核。
- 用阶段名称、结果版本、待确认事项、用户决定和下一步记录进度。恢复会话时按已记录的确认点继续。可继承用户已确认的范围，无须重复确认。用户明确只要求某阶段或指定核验任务时，交付该范围的结果，注明使用的输入与假设。

## 1. 判断品类

1. 用目标角色、典型任务、输入、期望输出和已知约束界定系统。给出一个主品类和判断依据，列出会扩大搜索范围的参考品类，说明每类可贡献什么。产品形态有歧义时并列说明哪些选择会改变候选池。
2. 用主品类和参考品类实际搜索开源项目，并盘点可复用的现有系统。按 [底座检索与核验手册](references/foundation-research.md) 查官方仓库、版本、许可、部署方式、入选理由和明显阻断，给出候选池。完成发现和初筛后，按手册给出初步匹配度百分比排名，默认详列前 10 名，其余列附表。逐个分点写明功能匹配、开源许可、二开风险、工程形态与集成、维护情况及与现有系统的关系。正式评分留在第 3 步。
3. 产品体验会影响品类或候选去留时，可安排子 Agent 查官方在线演示，或在用户已授权的环境和范围内试部署，打开真实页面，保留截图或可复现记录。实验的候选、环境、观察目标与交付字段见 [试部署与页面取证](references/foundation-research.md#2-试部署与页面取证)。

**请用户确认**主品类、项目业务边界和进入下一步的候选范围。暂时无法部署的候选可附证据局限继续初筛。

## 2. 拆解能力

1. 优先追踪一笔近期真实业务，从触发到完成，记录角色、操作、交接、异常、补救和结果。为可定位的原始材料编 E 号，区分观察事实、反馈、明确决定、推断与待验证事项。为卡点编 P 号并关联 E，记录频次、影响和测量口径。缺数据时给出最小取证动作。
2. 按业务流程拆关键能力 C 和可验证需求 R。每条 R 关联 P、C 和 E，或追溯已确认约束。写角色、前置、动作、结果和验收条件，按需要补充权限、异常、迁移与审计。标注一期或后续、必需或可选、确认状态及业务验收状态。
3. 从 R 选出所有候选共用的计分项、必需项、硬约束和允许的交付方式。业务需求来自目标流程和证据。候选的 README、页面和功能可用于查漏，新增需求仍需业务依据。

**请用户确认**关键能力、一期范围、必需项和正式对照口径。将确认的清单作为第 3 步输入。

## 3. 对照底座

1. 用第 2 步确认的同一套用例对照候选，可按能力清单补搜遗漏项目。锁定版本、部署模式和观察时间，筛查许可、数据、部署与集成等硬约束。记录淘汰原因和仍待核实的约束。
2. 逐项查目标版本的 README、官方文档、源码、测试或运行记录，判断具备、部分具备、不具备、待核实。每项给出适用版本、证据、支持方式与差距。需用实测验证时，写明可复现条件，使用已有授权的隔离环境。页面观察、技术验证和正式业务验收分别记录。
3. 按 [报告模板](references/kickoff-report.md) 输出候选表及逐项证据。表前列品类、候选数和关键能力，表内并列匹配度与四态计数。先用硬约束和必需项判断推荐资格，再比较二开、迁移、运维、升级与退出成本。明确整套底座、可复用组件和组合方案的区别，组合覆盖需有集成证据。

**请用户确认**拟采用的底座或组合、改用既有工具或自建等实施路线，以及接受哪些缺口和验证前提。未知项保留为条件，需要时留在本步补证据。

## 4. 沉淀方案

1. 把前三步确认的业务边界、能力、所选路径和关键缺口落实到业务方案。按项目需要写功能需求、用户角色与权限、业务流程与状态、业务规则与异常、验收与开工条件。每项追溯到用户决定、需求或证据，同时保留未决事项、责任和验证动作。
2. 根据证据给出开工建议。核心流程和关键依赖有可行证据时建议「可开工」。关键适配问题可验证时建议「先试点」，附通过和停止条件。关键需求或前提缺证据时建议「先验证」，明确取证动作。收益有限或硬约束无可行解时建议「暂缓」，写明恢复条件。
3. 按 [报告模板](references/kickoff-report.md) 整理七节报告。除非用户指定单一格式，默认交付同名 Markdown 与可离线打开的 HTML。核对阶段记录、必需 R 的证据、候选分数与逐项矩阵、缺口验证、两份文件内容和目录链接。

**请用户确认**方案范围、验收与开工条件。确认前标为待确认稿，确认后更新状态并交付定稿。
